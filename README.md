# Global Tech Terminal

글로벌 테크 기업 247개(260개 업종 매핑) 연구용 대시보드. GitHub Pages에서 모바일과 PC로 접근합니다.

## 1. 설치·배포
1. GitHub에서 새 **Public** repository를 `global-tech-terminal` 이름으로 생성합니다.
2. 이 ZIP 파일의 **내부 파일/폴더**(`index.html`, `data/`, `scripts/`, `.github/`, `requirements.txt`)을 저장소 **루트**에 업로드합니다. 숨김 폴더 `.github`가 빠지면 자동 갱신이 되지 않습니다. 파일 수가 많거나 숨김 폴더 업로드가 어려우면 GitHub Desktop으로 업로드합니다.
3. 저장소의 `Settings → Pages → Build and deployment`에서 `Deploy from a branch`, `main`, `/(root)`를 선택하고 저장합니다.
4. 배포 URL은 `https://GITHUB_USERNAME.github.io/global-tech-terminal/` 형태입니다. (실제 이름으로 바꿔야 합니다.)
5. `Settings → Actions → General → Workflow permissions`에서 `Read and write permissions`를 허용합니다. 조직/계정 정책상 막혀 있으면 관리자 설정이 필요합니다.
6. `Actions → Update company data → Run workflow`를 눌러 **기업 자료 첫 수집**을 진행합니다. `data/market.json`에 갱신된 데이터를 커밋하면 대시보드에 표시됩니다.
7. 이후 평일 하루 1회 자동 실행되도록 되어 있습니다. GitHub Actions 스케줄 실행은 지연되거나 정책상 비활성화될 수 있습니다.

## 2. 주가 차트가 비어 있을 때
네이버 차트 이미지나 TradingView 임베드 대신 일별 **실제 종가를 자체 차트**로 표시합니다. 일본 Kioxia (`285A.T`), 한국 SK hynix (`000660.KS`) 등 거래소별 코드를 수집기에 매핑했습니다. 일부 종목은 Yahoo Finance에서 데이터를 제공하지 않거나 호출을 제한할 수 있으며, 오류 시 빈 차트와 TradingView/Google Finance 원본 링크가 표시됩니다. 샘플/가상 시세는 넣지 않았습니다.

기업 탐색 일봉 차트는 `3개월 / 6개월 / 1년 / 3년 / 전체`를 지원하며 기본값은 1년입니다. 기존 고정 일수 방식과 최신 저장 거래일 기준을 유지해 6개월은 최근 186일 범위의 실제 관측만 표시합니다(3개월 93일, 1년 370일, 3년 1,100일). 상장 전이나 누락된 시세는 채우지 않으며, 다른 탭의 기간 선택과 수익률 카드는 변경하지 않습니다.

## 3. 실적
최근 4개 분기의 *분기 매출액*, *분기 영업이익*을 백만 **보고 통화** 단위로 표시합니다. OPM은 자동 계산합니다. 주가·시총은 가능한 경우 평일 갱신하고 실적 조회는 기본적으로 월요일/수동 실행 때만 시도합니다. 자산/사업 구조에 따라 영업이익 라인이 공급사 데이터에 없을 수 있습니다. 공시 원문과 비교 검증이 필요한 연구용 2차 데이터입니다.

## 4. 중요 제약
- Yahoo Finance/yfinance는 무료·비공식 데이터 경로이며 API 제한, 결측 및 약관 문제가 발생할 수 있습니다. 247개 종목에 대한 안정적 상업적 이용이 필요하면 적법한 유료 공급사로 교체해야 합니다.
- GitHub Actions 실행 시간이 길어지거나 429 오류가 나면 일부 종목은 이전 데이터로 남습니다. 각 종목의 `updated` 필드를 함께 보관합니다.
- 비미국 종목의 `marketCap` 보고 통화 환산 실패 시 임의 값 대신 빈칸을 둡니다.
- 미국 시장이 아닌 종목은 일부 티커가 잘못 매핑되었을 수 있습니다. `scripts/update_data.py`의 `lookup()`을 수정하세요.
- GitHub Pages는 공개 사이트입니다. 비밀번호나 비공개 API 키를 저장소에 넣지 마세요.

## 6. 데이터 품질 관리 (2026-10-17 정비)

- 246개 회사 전체의 차트·시총·분기 실적을 `data/coverage.json`과 `data/coverage.csv`에서 검사합니다. 차트와 시총은 246개 모두 확보했습니다.
- 240개 회사는 최근 4개 분기 매출/영업이익이 있습니다. Air Liquide, Schneider Electric, VAT, Henkel은 분기 매출은 있지만 영업이익은 반기·연간만 공시합니다. Kingboard Laminates는 반기·연간 공시 회사로 실제 반기 실적을 별도 표시합니다. DuPont은 연결 GAAP 영업이익 소계를 별도 제시하지 않으므로 검증된 계속영업 매출만 표시합니다. N/A는 0이 아닙니다.
- Everpure(구 Pure Storage)는 `NYSE:P`, Fiserv는 `NASDAQ:FISV`, LX Semicon은 KOSPI의 `108320.KS`로 수정했습니다. 이전 심볼은 마이그레이션합니다.
- 새로 보완한 실적의 공시 URL·기간·단위·확인일·파생 계산 근거는 `data/financial_backfill_asia.json`과 `data/financial_backfill_us.json`에 보관합니다. 이 파일들은 출처를 확인한 시점의 스냅샷이며 실시간 공시 수집기가 아닙니다. 기존 모든 회사의 모든 값에 대해 독립 감사가 이뤄졌다는 의미는 아닙니다.
- 시세 갱신일과 실적 확인일은 별개입니다. 정적 공시 스냅샷을 다시 적용해도 확인일을 오늘로 바꾸지 않습니다. 원문에서 반기 누적 실적만 공시한 경우 이를 임의로 2분기에 나누지 않습니다.
- 무료 시세 공급사의 일시 실패 시 기존 유효값을 보존하며, 모든 시세 요청이 실패하면 갱신을 성공으로 발표하지 않습니다. 조정종가용 대체 엔드포인트, 환율 조회 캐시, 원자적 JSON 저장, 전체 회사 회귀 검사를 사용합니다.
- 시총은 공급사 값입니다. LX Semicon의 최초 복구값은 최신 종가 × 회사가 공개한 발행주식수로 산출 후 USD/KRW로 환산한 값이며 화면에서 계산값으로 표시합니다. 모든 시총은 최신 실시간 값이 아닐 수 있으므로 표시된 기준일을 확인하세요.

## 7. 일일 시장 분석과 보존 아카이브

일일 결과는 **국내 시장 분석 / 미국 시장 분석** 탭에 게시합니다. 마감 브리핑과 독립 시장 히트맵 탭은 제거했습니다. 국내 KOSPI·KOSDAQ 히트맵과 미국 FINVIZ 히트맵은 각 시장 분석 안에 유지합니다. 국내 시황·이례적 등락·실적/콜은 날짜 선택으로 과거 기록도 볼 수 있습니다. 수급·히트맵·업종·신고가 등 독립 데이터 영역은 각 항목에 표시된 최신 검증일을 유지합니다. 과거 시황을 선택했다고 다른 최신 시계열을 과거 데이터로 재표시하지 않습니다.

- 기존 `#briefing/KR/YYYY-MM-DD`와 `#briefing/US/YYYY-MM-DD` 링크는 각각 `#korea/YYYY-MM-DD`, `#us/YYYY-MM-DD`로 연결합니다. 없는 날짜는 실제 게시된 최신 기록으로 되돌아갑니다.
- 국내 탭은 최신 항목별 검증일과 마감 시황을 히트맵보다 먼저 보여 줍니다. 거래량 동시조건의 이례적 등락과 실적·콜 확인 내용을 이 탭에 함께 표시하고, 출처·긴 설명은 기본 접힌 하단 영역에 둡니다.
- 페이지를 켜 둔 경우 보이는 시장 분석 탭은 5분 간격 및 다시 돌아올 때 게시 파일을 확인합니다. 동일 데이터는 화면을 다시 만들지 않고, 사용자가 명시적으로 선택한 과거 날짜는 새 자료가 있어도 유지합니다. 국내의 ‘최신 게시 자료 확인’으로 즉시 재조회할 수 있습니다. 이 확인은 게시된 JSON을 다시 받는 동작이며 실시간 시장자료 수집이 아닙니다.
- 승인된 일일 작업은 한국 실제 거래일 18:00 KST에 수집·검증을 시작하며 처리 후 게시합니다. 미국 정규장 마감 후 실제 완료 세션 자료를 검증하며 한국시간 07:00 KST에 점검을 시작합니다. 미국 작업은 화–토요일 KST에 점검하며 양국 휴장일·완료 세션을 검증합니다. 일정은 외부 작업으로 관리되고 이 저장소의 일반 시세 Actions와 별개입니다. 결과는 대시보드에 반영하며 일상적인 채팅 브리핑은 보내지 않습니다.
- 숫자와 출처가 검증된 범위만 갱신합니다. 공급사 지연·실패는 이전 날짜 또는 미확인을 그대로 남기며 전일 숫자의 날짜만 바꾸지 않습니다. 실적 발표·마감 반응·콜 원문 확인 여부는 별개입니다.
- 기존 `data/briefings.json`과 지난 거래일은 보존합니다. 이 파일은 국내 분석의 날짜별 시황·실적 자료 원본이며 예전 화면을 별도로 게시할 필요는 없습니다. 미국 신규 자료는 `data/us_analysis.json`의 완료 거래일 entry에 게시합니다.

### 데이터 구조와 매일 추가하기

`data/briefings.json`은 `schemaVersion: 1`, `updatedAt`, `entries`로 구성합니다. 각 entry의 고유 키는 `market` (`US`/`KR`) + `date` (`YYYY-MM-DD`)입니다. 필수값은 `status` (`partial`/`complete`), `title`, `sources`입니다. 확인하지 못한 숫자는 `null`로 두고, 공백·0·추정치로 대체하지 않습니다.

선택 섹션:

- `summary`: `{title, text, sourceIds}` 배열, `indices`: `{name, close, changePct, sourceIds}` 배열
- `sectors`: `{methodology, note, rows}`. 각 행은 `{name, ticker, benchmark, group, day, week, month, sourceIds}`. 수익률은 백분율 숫자입니다.
- ETF 행은 `instrumentType: "etf"`, 바스켓은 `"basket"`으로 구분합니다. ETF에는 `holdings: {status:"verified", asOf:"YYYY-MM-DD", sourceIds:[], top5:[{name,ticker,weightPct}]}`를 추가합니다. 운용사 실제 보유내역 기준일·출처와 비중 내림차순의 정확히 5개 보유종목을 기록하며 `티커(종목1 / 종목2 / 종목3 / 종목4 / 종목5)` 형식으로 표시하며 중복되는 ETF 풀네임과 행별 보유비중·기준일·출처 줄은 생략합니다. 실제 기준일과 출처는 하단 출처 목록과 데이터에 보존합니다. 현재 자료를 과거 거래일 자료로 간주하지 않습니다. 확인하지 못한 경우 `{status:"unverified", note:"미확인 이유"}`로 명시하고 추정 종목을 넣지 않습니다. 기존 3종목 바스켓은 ETF 상위 5종목으로 바꾸지 않습니다. 매일 새 분석 작성 때 기준일과 출처를 다시 검증하며 이전 보유내역의 날짜를 자동으로 오늘로 바꾸지 않습니다.
- `movers` / `highs`: `{criteria, note, rows}`. 각 행은 `{name, ticker, changePct, marketCapUSD, reason, kind, sourceIds}`. 거래량 검증값은 `volumeCurrent`, `volumePrevious`, `volumeChangePct`에 기록합니다. 국내 `movers.rows[].news`는 선택 필드 `{text, date, kind: "reported-context", sourceIds}`이며, 검증된 관련 뉴스가 있을 때만 짧게 표시합니다. 뉴스 날짜와 출처를 함께 보이고, 보도된 배경과 입증된 가격 원인을 구분합니다. 없으면 빈 문구를 추가하지 않습니다. 기존 `reason`은 선별 근거로 접힌 출처 영역에 보존합니다.
- `earnings`: `{note, rows}`. 각 행은 `{name, ticker, period, summary, metrics:[{label,value}], callHighlights:[], sourceIds}`. `callHighlights`에는 확인한 자료 유형을 명시합니다.
- `flows`: `{unit, asOf, note, sourceIds, rows:[{market, foreign, institution, individual}]}`. 양수는 순매수입니다.
- `watchlist` / `limitations`: 문자열 배열
- `sources`: `{id, title, url, note}` 배열. 모든 `sourceIds`는 같은 entry의 source ID를 참조합니다.

검증된 단일 entry 또는 여러 entries가 든 같은 구조의 JSON 파일을 준비한 뒤:

```sh
python scripts/manage_briefings.py --entry /path/to/verified-entry.json
python scripts/manage_briefings.py
python -m unittest discover -s tests -v
node tests/test_ui.cjs
node tests/test_briefing_ui.cjs
```

추가 도구는 같은 시장·날짜만 교체하고 과거 날짜와 다른 시장을 보존합니다. 유효하지 않은 날짜, 중복 날짜, 잘못된 출처 링크, 존재하지 않는 source ID, 무한대·NaN·숫자 문자열은 거부합니다. 검증 후 원자적으로 저장합니다. GitHub `main`에 검증된 변경을 커밋하면 기존 Pages URL에 반영됩니다.

이 UI는 뉴스·컨퍼런스콜을 자동 생성하지 않습니다. 별도로 승인된 수집 작업은 검증된 entry를 위 방식으로 추가할 수 있습니다. 기존 시세 자동 수집은 브리핑 내용/날짜를 바꾸지 않습니다. 기존 Actions 테스트 단계에 브리핑 검사도 포함했습니다.


## 10. 분석 내 히트맵 · 금리/매크로 탭

- `#us`의 히트맵: FINVIZ가 제공하는 공식 Maps 임베드 (`https://finviz.com/widgets/map?t=sec&st=d1&theme=dark`)로 S&P 500 업종별 1일 등락률을 표시합니다. 원본 페이지는 iframe 제한이 있으므로 넣지 않습니다. 원본 링크를 항상 함께 제공합니다. 기존 독립 탭의 `#heatmap` 링크는 브라우저 기록을 추가하지 않고 `#us`로 연결합니다.
- `#rates`: 공개 이용 가능한 FRED 차트와 공식 TradingView 위젯을 2열(모바일 1열)로 모읍니다. FRED 차트는 조회 시점 UTC 날짜부터 5년 전까지의 원본 PNG 차트를 사용하며, 조회 종료일을 데이터 최신 관측일이라고 표시하지 않습니다. 원본 제목·축·출처·로고를 유지하고 시리즈 링크, 단위, 빈도를 표시합니다. 매 방문 시 원본 제공자가 제공하는 이미지이므로 별도 API 키나 저장소 내 시계열 복제가 없습니다.
- 미국 10년 국채는 DGS10(%/일별), 10년 우량 회사채는 HQMCB10YRP(%/월별, AAA·AA·A 등급 액면수익률)입니다. 후자는 전체 투자등급 회사채 지수 수익률과 동일하지 않습니다. 별도로 ICE 전체 투자등급 원본 링크를 제공합니다.
- WTI와 Brent는 DCOILWTICO/DCOILBRENTEU 현물 가격(USD/배럴)이며 선물이 아닙니다. DEXJPUS/DEXKOUS는 각각 엔/1 USD, 원/1 USD입니다. 환율은 일별 관측이지만 공개 시차가 있습니다.
- 달러지수 차트는 연준의 교역 가중 광의 달러지수 DTWEXBGS(2006년 1월=100)입니다. ICE DXY와 구성·기준이 다르며 DXY로 표기하지 않습니다. DXY는 공급사 위젯에서 표시할 수 없음을 확인하여 별도 TradingView 원본 링크만 제공합니다.
- ICE 하이일드 수익률(BAMLH0A0HYM2EY)과 하이일드 스프레드(OAS, BAMLH0A0HYM2)는 TradingView에서 생성한 공식 Advanced Chart 위젯으로 제공합니다. 심볼 `FRED:BAMLH0A0HYM2EY` / `FRED:BAMLH0A0HYM2`, 기본 5년(`60M`) 설정과 제공사 로고·저작권·원본 링크를 유지합니다. OAS는 국채 대비 옵션조정 금리 차이로, 차트의 % 표시는 %p로 읽습니다(예: 3.00%p = 300bp). 채권의 절대 수익률과 구분합니다. ICE 시계열을 다운로드하거나 저장소에 복제하지 않습니다. FRED에 수록되어 있다는 사실만으로 모든 시리즈가 공개 재배포 가능한 것은 아닙니다.
- 외부 차트는 제공사 장애·네트워크·브라우저 설정에 따라 표시되지 않을 수 있습니다. 오류 안내·차트 다시 불러오기·직접 원본 링크를 유지하며 임의 값/가짜 차트로 채우지 않습니다. FRED가 HTTP 200으로 빈 이미지를 반환할 수 있어, 화면이 비어도 오류로 감지되지 않는 경우에는 다시 불러오기/원본을 이용합니다. 지표별 시차와 주기 때문에 같은 기준일의 실시간 수치가 아닙니다.
- 접근성: 네 탭(기업 탐색·금리/매크로·국내 분석·미국 분석)은 방향키/Home/End 탐색, ARIA 선택 상태, 개별 해시 링크와 뒤로/앞으로 이동을 지원합니다. 기업 선택/검색과 각 시장 분석의 날짜 선택을 지원합니다.

## 11. 국내 시장 분석

국내 시장 분석 탭 `#korea`는 수급·자금 전용 `data/korea-market.json`과 기존 `data/briefings.json`의 최신 KR 항목을 함께 사용합니다. 날짜별 분석 원본을 복제하지 않고 메모리에 공유하며 기업·금리·미국 분석 탭을 유지합니다. 각 시장의 히트맵은 분석 안에서 제공합니다.

- 표시 순서는 **항목별 검증일 → KOSPI·KOSDAQ 히트맵 → 마감 시황 → 당일 시장 수급 → 투자자별 일별 순매수 → 업종 수익률·확장 테마 수급 → 종목 순매수·거래대금 → 지수 구성종목 등락률 → 52주 신고가 → 이례적 등락·실적/콜 → 예탁금·신용잔고**입니다.
- 마감 시황은 최신 KR 브리핑의 제목·지수·요약을 사용합니다. 휴장일 후속 뉴스는 별도 접기/펼치기로 구분합니다. 당일 수급 숫자는 아래 차트의 최신 실제 관측과 동일하며 브리핑의 과거 집계시각 자료와 혼합하지 않습니다.
- 업종별 1일/1주/1개월 수익률은 `sectorReturns`의 검증된 세부 업종 32행(ETF 13개, 대표 바스켓 19개)을 사용합니다. 과거 아카이브 자료는 그대로 보존합니다. 업종명과 실제 ETF 상위5 보유종목을 표시하고 티커는 출처로 옮겼습니다. 바스켓은 별도 표시하며 고정 대표 종목의 각 기간 시작 동일가중 수익률입니다. 반도체·건설 중복과 혼합 광역 업종을 정리하고 전기전자·IT서비스·인터넷·조선·원자력·전력설비·태양광·풍력·호텔·카지노·백화점·엔터·우주·로봇 등을 구분합니다. 한국·미국 분석의 수익률 목록은 그룹에 관계없이 기본 1일 수익률 내림차순으로 표시합니다. 미확인은 마지막에 두고, 선택한 기간의 숫자 정렬을 지원하며 각 행의 계산·구성 근거를 펼칠 수 있습니다.
- 52주 신고가는 기존 브리핑의 시총 상위300 선별 범위와 장중고가 기준을 유지합니다. 최초 299개 당일 일봉·294개 전체52주 이력 확인, 검증 제외1개이며 KT&G와 코웨이2개입니다. 시총 목록은10/17조회 최신 스냅샷으로10/16종가 시점고정 순위가 아님을 출처 설명에 보존합니다.

- KOSPI/KOSDAQ 외국인·기관·개인 **일별 순매수**: 2023-10-17부터 2026-10-16까지 시장별 730개 실제 관측을 SVG 차트와 일별 표로 표시합니다. 수급 차트는 외국인·기관만 표시하고, 1주/1개월/3개월/6개월/1년을 최근 5/21/63/126/252개 실제 거래일 관측으로 전환합니다. 기본은 1개월(21개)입니다. 당일 숫자 요약에는 개인을 유지합니다. 마우스·터치 및 키보드 날짜 탐색을 지원합니다. 예탁금·신용잔고의 별도 3개월/1년/3년 범위는 유지합니다. 원화 자료를 억원으로 나눕니다. 외국인은 9000 코드이며 기타외국인 제외, 기관은 원자료의 8개 세부 범주 합입니다. 다른 투자자 범주가 있으므로 세 투자주체의 합이 0일 필요는 없습니다.
- 외국인/기관 순매수 상위15: 최근 5개 거래일 날짜 선택과 **1일/주간/월간** 집계 선택을 제공합니다. 통합/KOSPI/KOSDAQ별 순위를 볼 수 있습니다. 기간 순위는 NAVER가 직접 계산한 기간 순매수대금을 사용하며 일별 상위10을 더하지 않습니다. 최초 MONTH의 실제 공급사 조회창은 2026-09-15~2026-10-16입니다. 순위별 실제 조회기간을 표시합니다.
- 종목 범위는 보통주 중심(ST 유형·우선주 명칭/코드 필터)이며 ST 스팩 포함, RT 리츠·외국주식·예탁증권·펀드형 제외입니다. 과거 4일은 연합뉴스의 KRX·연합인포맥스 15:30 자료, 최신·기간 자료는 NAVER KRX 조회이므로 집계 시각과 정밀도가 다를 수 있습니다. 이러한 자료를 같은 모집단의 정정 확정값으로 간주하지 않습니다.
- 거래대금 상위20은 **최신 확인 거래일**을 별도 표시합니다. 위 순매수 집계기간과 함께 바뀌지 않습니다. 실제 `tradeAmount`를 사용하며 종가×거래량 추정이 아닙니다. 최초 수집 시 2,869개 주식 목록으로 통합 상위20 순위를 대조했습니다.
- 투자자예탁금은 **시장 전체**입니다. 이를 KOSPI/KOSDAQ으로 나누지 않습니다. 신용잔고는 **신용거래융자만** KOSPI와 KOSDAQ으로 나눕니다. 대주·예탁증권담보융자·미수금은 포함하지 않습니다.
- 자금 3개 시계열은 2023-10-17~2026-10-15의 732개 공개 관측입니다. 일부 연말 통계 보고일은 주식 거래일과 다릅니다. KOFIA 원 발행처 조회 장애로 공개 재배포 자료를 이용하였고, 과거 679일 시장별 신용융자와 최근 68일 합계를 독립 자료로 교차검증했습니다. 원통계의 정정 및 공개 지연 가능성이 있으며, NAVER 과거 예탁금과 15일의 차이가 발견되어 일관된 KOFIA 재배포 스냅샷을 유지했습니다. 출처 경로와 원단위는 데이터에 보존합니다.
- 미확인 값은 `null`/빈 배열과 사유로 기록합니다. 추정, 보간, 임의 0 채움, 상위 종목 일부로 전체 테마 합산하기를 하지 않습니다. 자료 범위·출처는 각 카드의 접기/펼치기에서 확인할 수 있습니다.

### 실적 기업명 옆 정규장 / 발표 후 시간외 가격 (2026-10-18)

`earnings.rows`의 선택적 확장 필드이며 기존 `schemaVersion: 1`을 유지합니다. 새 게시·실적 보강 작업에서는 각 행에 아래 항목을 채웁니다. 과거 필드 없는 행도 읽을 수 있으며 미확인으로 표시됩니다.

- `releaseTiming`: `{session, publishedAt, sourceIds, note}`. session은 `before_open` / `during_session` / `after_close` / `unknown`. 공식 발표 공지 또는 회사 발행 보도자료로 장전·장중·장후를 확인하고 출처를 남깁니다. `publishedAt`은 실제 실적 배포 시각의 offset 포함 ISO 8601이며, 분까지 확인할 수 없으면 `null`. 콜 시작 시각이나 예약 공지 게시 시각을 실적 배포 시각으로 쓰지 않습니다.
- `priceReaction.currency`: `USD`.
- `priceReaction.regular`: `{date, previousDate, closedAt, close, previousClose, changePct, sourceIds}`. 실제 실적 발표일의 정규장 종가 / 직전 거래일 정규장 종가를 같은 가격 조정 기준으로 조회합니다. `changePct = (close / previousClose - 1) * 100`. 원값과 계산 정밀도를 보존하고 표시에서만 기존 방식으로 최대 소수 둘째 자리 반올림합니다. `closedAt`은 실제 거래소 마감 시각(단축장 포함)이며 일봉의 09:30 타임스탬프나 수집 시각이 아닙니다. 날짜별 실제 거래 세션도 별도 확인해야 합니다.
- `priceReaction.afterHours`: `{status, price, changePct, observedAt, sourceIds, note}`. status는 `verified` / `unverified` / `not_applicable`. 장후 발표 기업만 발표 이후 시간외 반응을 연결합니다. `changePct = (price / regular.close - 1) * 100`; 전일 종가, 시가, 총 당일 수익률과 혼용하지 않습니다. `observedAt`은 제공사가 명시한 가격 관측 시각이며 offset 포함 ISO 8601. 같은 ET 날짜의 정규장 마감 이후이면서 실적 발표보다 엄격히 늦고 20:00 ET 이전인 최신 검증 가능 관측만 씁니다. 실제 발표 시각을 모르면 안전하게 `unverified`로 둡니다. 다음날 프리마켓, overnight, 발표 직전 값, 정체된 정규장 가격을 대체하지 않습니다.
- 가격 또는 시각을 검증하지 못한 경우 `price`, `changePct`, `observedAt`은 전부 `null`, 상태 `unverified`와 이유를 저장합니다. 수집 당시 최신 여부·유동성·지연을 출처에서 확인하고 필요하면 note에 명시합니다. 정확히 변화가 없는 검증된 시세만 0%가 됩니다.
- 장전/장중 발표는 `afterHours.status = not_applicable`, 값은 null로 남깁니다. 해당 당일 정규장 수익률을 `발표 전`이라고 부르지 않습니다. 발표 세션도 미확인이면 `unknown` / 시간외 `unverified`를 씁니다. 발표일보다 나중 날짜의 종가를 가져오지 않습니다.

### 커넥터 게시 요청 묶기 (2026-11-02)

GitHub 커넥터로 게시할 때 작은 UTF-8 텍스트 변경은 `create_tree.tree_elements`의 `content`에 함께 넣는다. 파일별 `create_blob` 호출을 줄이는 GitHub 공식 Trees API 기능이며, 승인 절차를 끄거나 우회하는 기능이 아니다. 필수 승인은 각 실제 요청에 그대로 적용되므로 승인 창 개수나 무승인 게시를 보장하지 않는다.

읽기 전용 준비 도구 예시:

```sh
python scripts/prepare_connector_publication.py --root . \
  --expected-head <검증한-main-40자리-SHA> \
  --base-tree <해당-main의-tree-40자리-SHA> \
  README.md scripts/prepare_connector_publication.py tests/test_connector_publication.py > /tmp/publication-plan.json
```

- 명시한 파일만 읽으며 네트워크·Git 쓰기·게시·설정 변경을 수행하지 않는다. 파일 경로, UTF-8, 원시 크기, SHA-256 및 Git blob SHA를 점검·기록한다. 삭제·심볼릭 링크는 지원하지 않는다. 비 UTF-8/바이너리는 변환하지 않고 별도 blob 대상으로 표시하여 원시 바이트를 보존한다.
- 기본 1 MiB는 **로컬 inline 항목의 JSON 전송 예산**이지 GitHub 공식 API 제한이 아니다. 예산 밖 파일은 `separateBlobFiles`에 표시하며, 기존 승인된 blob 업로드 절차를 유지한다. 예산을 넘겼다는 이유로 승인 거절 뒤 다른 경로로 재시도하지 않는다.
- `inlineEntries`와 별도 업로드에서 검증한 blob SHA 항목을 **한 create_tree**에 넣고, 확인한 최신 `base_tree_sha`를 반드시 지정한다. 같은 항목에 `content`와 `sha`를 동시에 넣지 않는다. 준비 당시 head와 현재 main이 다르면 겹치는 변경을 보존·통합하고 전체 검증 및 계획 생성을 다시 한다.
- 이후 단일 `create_commit`, `update_ref(expected_sha=<검증한-main>, force=false)`를 사용한다. 실패 또는 결과 불명은 실제 원격 상태를 확인하고 무조건 재실행하지 않는다. 승인 거절은 우회하지 않고 정확한 차단을 보고한다.
- 기존 전체 테스트·스키마 검증·캐시 자산키 규칙·해당 커밋 Pages 성공·공개 파일/화면 확인은 생략하지 않는다. 문서/준비 도구만 변경하면 불필요한 데이터·캐시 버전키 변경은 하지 않는다. 이미 게시된 동일 자료를 이 방식 시험을 위해 다시 게시하지 않는다.
